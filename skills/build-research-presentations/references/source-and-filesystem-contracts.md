# 素材与文件系统合同

## 来源优先级

遇到冲突时按以下顺序处理：

1. 用户对本次汇报的最新明确说明；
2. 对应模块的当前规范文件；
3. `PROJECT.md`中已经确认的当前状态；
4. 既有汇报和历史工作记录。

用户最新说明与规范文件冲突时，必须显示具体差异。它可以指导本次汇报的表达，但不得被静默当成已经更新的项目规范。

## 模块读取边界

| 来源 | 可以读取 | 不得做 |
|---|---|---|
| `PROJECT.md` | 当前状态、卡点、短期下一步、已确认决定 | 不把意见历史全集搬入 PPT；不写回 |
| `01` | 背景、缺口、Novelty、研究问题 | 不另造并行立项版本 |
| `02` | 故事、证据、路线、数据和图意图 | 不修改设计或把假设写成结果 |
| `03` | 工作事实、主库结果、单元解释 | 不重算、不把全部历史塞进当前故事 |
| `04` | 已形成的 Fig、自制图和图注 | 不改变 panel 科学内容或重拼论文 Fig |
| `05` | 当前写作、投稿、审稿状态 | 默认不把稿件正文作为汇报素材 |
| 既有 PPT | 历史表达、样式和上次时间点 | 不把旧 PPT 当成当前科学事实的最高来源 |

## 视觉参考选择

- 用户明确给出参考 PPT 时，以该文件为唯一视觉参考，并在页面故事板中写明。
- 用户只要求“延续以前风格”且项目内有多份候选 PPT 时，优先选择同一汇报场景、最近一份已接受的汇报；若候选之间的视觉体系不同且选择会明显影响成品，先请用户指定。
- 历史 PPT 可以提供母版、版式、字体、图文比例和页面类型，但不能决定当前材料的科学结论或结果取舍。

## 写入边界

默认只允许：

```text
<project-root>/项目汇报/组会汇报/
<project-root>/项目汇报/项目汇报/
```

用户明确指定项目外输出路径时可以按其要求交付副本，但不要因此改变项目内归档。除目标 PPT 外，项目材料保持只读。

所有中间代码、渲染图、素材副本和检查文件放入本次任务独占的临时目录。结束前只删除本次任务创建的准确临时路径，不使用通配符，不删除其他任务或用户文件。

## 文件命名与归档

建议命名：

```text
组会汇报/YYYY-MM-DD_组会汇报_<简短主题>.pptx
项目汇报/YYYY-MM-DD_<场景>_<项目名>.pptx
```

- 同一场汇报制作期间持续修改当前工作文件，不因小改产生多个版本。
- 用户接受的最终 PPT 才成为归档；临时预览不归档。
- 同名文件存在时，先判断是否为同一场未完成汇报。不是同一场时补充主题或使用 `_v2`，不得静默覆盖。
- 不自动回写旧汇报，不创建永久大纲、素材清单或汇报日志。

## 对外边界

- 默认只在本地生成文件。
- 上传、发邮件、创建共享链接、发布或把未发表结果发送给外部人员，均需独立明确授权。
- 听众包含项目外人员时，先让用户确认哪些未发表结果可展示。
- 演讲者备注默认使用项目相对路径。若最终文件将直接发给外部人员，提醒用户检查这些内部来源标记是否应保留或改为非敏感标签。

## 状态交接

本 Skill 不修改 `PROJECT.md`。任务结束时仅在确有状态变化时报告：

- 完成了哪一场汇报；
- 最终文件路径；
- 暴露了哪些项目级缺口、冲突或待判断事项；
- 是否可能影响 `01`、`02`、`03`、`04`或`05`；
- 建议交给 `$manage-research-project` 的最小状态事实。
