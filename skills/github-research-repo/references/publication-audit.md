# 审计与公开前检查

## 机械审计与语义审计

`scripts/audit_repository.py`负责可确定检查：

- 工作树全部文件，包括 ignored 和 untracked；
- tracked、staged 和 Git 状态；
- 禁入路径、文件类型、大文件和未知二进制；
- 常见秘密、私钥和本机绝对路径；
- README 必需章节和公开前占位；
- `--public`时的完整 Git 对象历史；
- 远端 URL 中的嵌入凭据和本地已知 upstream 差异。

agent 继续负责：

- 方法文档和代码是否真的对应实际研究流程；
- 工具版本、命令、参数、输入输出与执行顺序是否有证据或用户确认；
- 直接命令流程是否逐步完整记录，而非只保留笼统的工具名；
- 参数化是否改变科学逻辑；
- 资源来源和许可证是否允许再分发；
- README 的运行命令、输入输出和复现边界是否真实；
- accession、DOI、受控访问和 embargo 状态；
- 远端 owner/name、默认分支和实际可见性；
- 网络检查是否基于最新远端状态。

脚本成功不能替代这些语义判断。

## Private 阶段

每次本地整理和 commit 前检查：

- 只有用户选择的内容进入；
- 没有数据、结果、图片、内部文档、缓存和秘密；
- 绝对路径已经参数化；
- repo 副本和方法记录与 `03` 或用户确认事实的差异已说明；
- 未核实的版本、命令、参数或参数理由已明确标注，没有被写成已证实事实；
- README 与当前目录同步；
- 最小运行或静态检查通过；
- dirty worktree 中无未披露的用户改动。

private 阶段允许 README 存在明确、真实的未决占位；脚本将其报告为 warning。

## Push 前

除 private 检查外：

- commit 范围已经获批；
- 目标远端和分支已经获批；
- 远端实际为 private；
- fetch 状态足以判断没有领先或分叉；
- 本地没有待推送之外的意外 commit；
- 网络或认证失败时不会重复盲推。

## Public 前

运行 `audit_repository.py <repo> --public`，并补充：

- 扫描全部 Git 历史，而不只看当前工作树；
- 检查 README 所有占位、链接、运行命令和数据获取说明；
- 解决会影响复现的所有未核实工具版本、命令、参数和执行顺序；
- 确认不存在内部项目名、样本标识、账号、服务器和存储路径；
- 确认必要资源许可；
- 确认用户已指定当前方法内容的公开节点，且公开时点符合项目、论文、合作、专利、许可和数据限制；
- 确认最终架构和读者入口；
- 确认可见性变更的具体远端；
- 公开后重新读取远端可见性和内容。

历史中出现过数据、结果、秘密、内部文档或大文件时，阻断公开。删除当前文件不消除历史污染。

## 审计发现分级

- **blocker**：禁止进入或公开的内容、秘密、大文件、未知二进制、缺失 README、public 占位、历史污染或边界不完整。
- **warning**：private 阶段未决占位、内部 symlink、未核验远端可见性或需人工确认的语义问题。
- **fatal/incomplete**：路径不是仓库、Git 不可用、历史读取失败或审计无法完成。

blocker 未解决时不 commit、push 或 public。fatal/incomplete 时不得声称审计通过。

## 失败处理

| 情况 | 处理 |
|---|---|
| dirty worktree 与本次范围重叠 | 停止修改，保留用户改动 |
| 远端领先或分叉 | 停止 push，报告 ahead/behind |
| 用户确认的公开节点前远端已经 public | 停止新增和同步，报告暴露状态 |
| 无网络或认证 | 完成安全的本地工作，明确未执行远端动作 |
| 秘密已进历史 | 阻断；不自动改历史 |
| 方法或代码需改变科学逻辑才可移植 | 返回 `03`让用户判断 |
| public 后发现问题 | 立即报告；下线、删除或历史修复需独立批准 |
