# 科研方法与代码仓库内容合同

## 仓库角色

`<project-root>/Git/` 是读者向的科研方法与代码复现材料，也是本 Skill 在需要维护内容时按需创建、克隆或接管的本地工作区；它不必在调用 Skill 前存在。它说明实际如何完成分析：每一步使用什么工具和版本、运行什么脚本或命令、各参数如何设置与解释、输入输出如何衔接，以及复现边界是什么。

命令本身就可以是方法的正式实现；不要因为某个流程没有单独的脚本就排除它。它不是项目备份、`03` 镜像、结果仓库、论文正文或内部规划副本。

## 允许进入

- 用户明确选择的科研脚本；
- 基于实际执行证据整理的读者向方法文档；
- 按实际顺序记录的直接命令、工具版本、参数、输入输出和上下游关系；
- 与脚本配套的配置；
- 环境和依赖描述；
- Snakefile、Nextflow、CWL、Dockerfile、conda/renv/requirements 等工作流与环境文件；
- 为方法代码服务的必要测试和检查代码；
- 运行所必需、体积小、非项目数据、来源和许可允许再分发的辅助资源；
- README、`.gitignore`及用户明确批准的许可证或引用文件。

绘图脚本不因“绘图”自动排除。若它是研究方法复现的一部分且用户明确选择，可以进入；生成的图和结果不能进入。

## 明确禁止

- 任何真实项目数据或其裁剪、压缩、转码版本；
- 图片、论文图版、分析结果、统计输出和中间产物；
- 整个 `03`工作记录、日志、当天结果或主库副本；
- `PROJECT.md`、意见、内部进度和项目汇报；
- `01_立项与选题论证.md`、`02_实验设计.md`、`04_结果主库/`和`05_论文全周期/`内部材料；
- 缓存、临时文件、环境目录、编辑器状态和操作系统杂项；
- token、密码、私钥、凭据、`.env`或敏感配置；
- 未公开样本、受试者、合作者、账号、服务器、存储位置和内部地址；
- 与研究方法无关的探索脚本、临时排查代码和一次性命令；
- 未经证据或用户确认的工具版本、命令、参数值、参数理由或执行顺序；
- 10 MiB 及以上文件、未知二进制和来源或许可不明资源；
- 试图用 Git LFS 绕过上述边界的内容。

不确定是否属于数据、结果、秘密或允许再分发资源时，默认阻断并让用户判断。

## 必要辅助资源

辅助资源必须同时满足：

1. 没有它，读者无法理解或运行代码；
2. 它不是项目数据、结果或其变体；
3. 小于 10 MiB；
4. 不含敏感信息；
5. 来源和许可允许再分发；
6. README 解释用途。

合成或玩具数据只有在明确标记为合成、不会泄露项目信息、许可清楚且用户批准时才可进入。

## 目录组织

结构依赖 `02` 技术路线，但按**实际怎么跑**组织：

- 一个目录或方法章节对应读者能理解的逻辑运行步骤；
- 粒度跟随真实脚本、命令链和依赖，不机械跟随 Methods 句子；
- README 或方法文档解释实际步骤与研究方法之间的关系；
- 不强制 `src/`、`workflow/`或任何语言框架；
- `02`过时或缺失时，可以依据用户说明和真实代码整理，但要明确结构依据并提醒检查 `02`。

已有目录因 `02`变化需要重命名、移动或删除时，先展示迁移方案，不静默追随。

## `03` 到 repo 的晋升

| | `03` | `Git/` |
|---|---|---|
| 服务对象 | 自己和科研执行 | 需要理解或复现方法的读者 |
| 权威内容 | 当时真实怎样执行 | 当前如何准确分发和说明实际方法 |
| 路径与环境 | 可以保留真实历史 | 必须去敏和可移植 |
| 历史 | 完整工作记录 | 由 Git 保存读者向版本历史 |

晋升使用复制，不使用移动。允许在 repo 副本中：

- 把绝对路径改成参数或相对路径；
- 把秘密配置改成环境变量或安全示例；
- 增加参数说明、错误提示和最小运行入口；
- 调整目录和文件名以表达实际步骤；
- 增加不改变科学逻辑的测试。

若修改改变算法、样本范围、阈值、统计方法、结果或科学解释，停止。`03`仍是真实执行历史；是否回去修改并重跑由用户决定。

## 方法与命令记录合同

对每个实际步骤至少记录：

- 步骤名称、目的和在整体方法链中的位置；
- 工具名、实际版本和可核验的工具来源；
- 实际执行的完整命令，用代码块保留换行、引号和参数顺序；
- 每个关键参数的实际值、含义和设定依据；默认值也要在影响复现时说明；
- 输入类型、安全的路径模式或取得方式，不放入项目数据；
- 输出类型及其作为哪一个下游步骤的输入；
- 工作目录、环境、容器、资源要求或其他必要前提；
- 证据状态：已从原始记录核实、用户明确确认，或仍未核实。

若一个分析由 4 条命令组成，按实际顺序写成 4 个步骤，并明确前一条的什么输出被后一条消费。只有在语义不变且转换已披露时，才可提供另外的可移植命令；必须与“当时实际命令”分开标识。

## README 最低合同

README 至少包含：

```text
# <研究项目或论文标题>
## Overview
## Repository map
## Requirements
## Workflow
## Data availability
## Reproducibility boundary
## Citation / license
```

每个工作流步骤说明：

- 目的；
- 工具、版本、脚本和配置；
- 输入类型及取得方式，只描述或链接，不附数据；
- 实际运行命令及证据状态；
- 输出类型，只描述，不附结果；
- 关键参数的值、含义和设定依据；
- 环境、工作目录、上下游依赖和注意事项。

accession、DOI 或链接尚不存在时保留真实占位状态，不编造编号。private 阶段可保留明显占位；公开前必须解决，除非受控访问本身就是最终状态。

README 不复制 `01/02/05` 的内部论证或稿件内容，也不暴露项目内部绝对路径。

## 来源关系

不创建独立 provenance 文件。每次任务报告记录源路径与目标路径；README 只解释读者需要的运行步骤，不泄露内部 `03`路径。后续晋升仍由用户明确指定来源。
