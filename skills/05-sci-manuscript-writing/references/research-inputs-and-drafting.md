# 科研输入与正文撰写

## 输入优先级

按任务需要定向读取，不默认把全部文件载入上下文：

1. `02_实验设计.md`：故事板块、核心认识、证据、成立标准、主技术路线和 Fig 意图，是正文骨架与 claim 清单的主要来源。
2. `04_结果主库/`：已批准 Fig、同名图注和图片规划，是 Results 的正式视觉证据。
3. `01_立项与选题论证.md`：研究问题、背景、策略判断和 novelty，是 Introduction 的主要上游材料。
4. `03_数据与分析/`：只在需要精确方法、真实数值、统计量或结果解释时定向读取对应正式记录。
5. `PROJECT.md`：只读当前状态、已确认决定和卡点；它不是科学事实的替代来源。
6. 用户明确指定的模板、目标期刊要求和既有稿件。

缺少某个固定文件时，不凭空补齐。使用用户当前提供的可靠材料继续能做的部分，并明确剩余缺口。

## 写作就绪检查

在从零起草整节或整篇正文前，建立最小写作蓝图：

| 项目 | 内容 |
|---|---|
| 章节或故事板块 | 当前要写什么 |
| 本节目的 | 读者读完应理解什么 |
| 核心 claim | 允许写出的认识 |
| 支撑证据 | 数据、分析或逻辑依据 |
| 对应 Fig/Table | 正式图表及 panel |
| 来源 | 项目相对路径和稳定编号 |
| 引用需求 | 现有引文或 `[CITE: ...]` |
| 缺口 | 数值、图、证据或决定是否不足 |

按以下状态判断：

- **可写**：claim、证据和必要来源明确。
- **可写但待引用**：科学内容有依据，外部论断缺正式文献；保留具体 `[CITE: ...]`。
- **只能写骨架**：结构明确但关键结果或数值尚缺。
- **不可成文**：会迫使模型虚构证据、数值、方法或结论；先报告缺口。

## 撰写规则

- 语言由用户当前请求决定；不把语言当作启动模式。
- 优先按“目的或问题 → 方法/比较 → 关键观察 → 限定后的认识 → 图表引用”组织 Results 段落。
- Methods 只写实际采用的方法。02 提供路线，03 提供必要的执行细节；两者不一致时报告冲突，不自行选择。
- Introduction 使用 01 的研究问题与 novelty，但外部事实必须有现有引用或具体占位符。
- Discussion 区分结果直接支持的认识、与文献的关系、合理解释和仍待验证的机制。不得把相关性写成因果，不得把可能性写成已证实机制。
- Abstract、标题和关键词应在主体证据稳定后生成，除非用户明确要求先给工作版本。
- 翻译保持原意、数值、限定语、引用、图表引用和术语一致；发现原文逻辑漏洞时标出，不暗中修补。
- 修改先诊断科学逻辑、结构或语言问题，再给出适合当前风险的改法；不静默重写科学含义。
- 用户指定前作或模板只提供结构与表达参考，不能把其中事实、数值或引用直接移植为当前项目证据。

## 引文占位符

暂时无法落实的引文使用可检索的具体占位符，例如：

```text
[CITE: 早期研究发现海洋病毒辅助代谢基因参与宿主营养代谢]
```

不要使用缺乏主题信息的 `[CITE]`，也不要在写作阶段虚构作者、年份或 DOI。
