# 已有图表的稿件集成

本工作台只把已有、已确认的图表集成进稿件，不生成科研图、不运行分析、不改变图中科学内容。

## 来源与边界

- 优先读取 `04_结果主库/图片规划.md`、`04_结果主库/Fig/Fig_*.svg` 及同名图注；兼容用户明确指定的 PNG、TIFF、JPEG、SVG、PDF 或其他已有文件。
- `04_结果主库` 始终只读。不要重命名、覆盖、重新拼版或回写源图。
- 期刊要求的稿件内缩放、位置和格式适配写入当前活动稿件；初稿阶段默认直接写入初稿，只有用户要求时才创建副本或启用修订模式。若必须生成派生图片，保持 04 源文件只读，并只写入本轮请求指向的 05 附属位置。
- 需要重画数据图、改变 panel 科学内容、重新组合 Fig 或生成新图时停止并说明应切换到负责科研图构建的 skill。

## 插入图表

插入前在内部确定：

- 源文件及其稳定 Fig/Table 身份；
- 目标 DOCX，以及用户是否要求副本或修订模式；
- 精确插入锚点；
- 编号、图注或表题；
- 单栏/双栏宽度或用户指定尺寸；
- 是否存在正文引用和交叉引用域。

用户要求“直接插入、放进稿件、编号并引用、你看着处理”等，且来源图、目标稿件和插入位置可确定时，直接完成插图、编号、图注和正文引用，不额外要求确认。用户要求“先给插图方案、先看图注、不要写文件”时，只在会话中展示方案；明确要求先预览时，再展示插入位置、显示尺寸、图注/表题、编号变化和受影响的正文引用。只有来源图、插入锚点或编号存在无法消除的歧义时才询问。

## 编号与引用一致性

识别并统一但不要盲目替换以下写法：

- `Figure 1`、`Fig. 1`、`Fig 1`；
- `Table 1`、`Tab. 1`；
- 子图引用，如 `Fig. 2A-C`、`Figure 2a`；
- 图注、表题、正文、交叉引用域以及 Figure/Table List 中的编号。

检查：

- 重复编号、断号和顺序异常；
- 正文提及但不存在的图表；
- 有图注/表题但正文未引用的孤立图表；
- panel 标签与正文引用不一致；
- 重编号后遗漏的正文引用或域；
- Figure/Table List 与正文不一致。

如果用户已明确要求直接处理且映射关系唯一，则一次性同步更新图注/表题、正文引用和相关列表，写后全局扫描；不要仅修改其中一处。若范围或映射存在歧义，先展示完整旧号 → 新号映射和受影响位置并澄清。

## 图注、表题与列表

- 从 02 证据映射、03 已记录解释、04 同名图注和实际图表生成内容，不虚构样本量、统计方法、显著性或缩写定义。
- 统一标题句、panel 标记、缩写、单位、统计说明、标点和句末格式。
- Figure List 和 Table List 从最终图注/表题生成或刷新；不维护与正文脱离的第二份事实源。

## 分辨率

对位图报告：

- 像素宽高；
- 元数据 DPI（如存在）；
- 按文档实际显示尺寸计算的有效 DPI；
- 与用户或期刊阈值的比较。

不要只看元数据 DPI。对 SVG、矢量 PDF 等报告为矢量源，并检查嵌入或转换后是否仍保持矢量；不要把矢量图误报为低 DPI。不得擅自上采样来伪装分辨率达标。

## 写后视觉检查

渲染文档并检查图片是否缺失、拉伸、模糊、被裁切或跨页异常；图注/表题是否紧邻对应对象；分页、环绕、宽度、字体和顺序是否符合当前稿件要求。
