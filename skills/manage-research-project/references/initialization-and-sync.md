# Initialization, synchronization, and material intake

## 共同入口

1. 确认 `$manage-research-project` 已由用户显式开启。
2. 简短说明“00科研项目驾驶舱已开启”。
3. 从用户明确路径或无歧义上下文确定唯一项目根目录。
4. 递归只读扫描项目；需要时读取隐藏材料，但不要遍历 Git 内部对象。
5. 如果存在 `PROJECT.md`，完整读取。
6. 在分类、理解和提出方案期间保持只读。

不能从目录整齐程度、文件数量或某个目录是否存在直接判断项目阶段。要根据数据、脚本、结果、图片、稿件、投稿材料、审稿材料和用户说明理解实际进度。

## 判断新项目或进行中项目

新项目常见信号：

- 根目录为空或接近为空；
- 没有材料表明科研工作已经开始；
- 用户明确表示这是新项目。

进行中项目常见信号：

- 已有数据、脚本、分析结果、图片、稿件、投稿或审稿材料；
- 已有计划或状态记录；
- 项目材料位于用户明确指出的外部或历史目录；
- 目录虽然杂乱，但材料能证明工作已经推进。

提出写入或复制方案前，说明判断、证据路径、可能的另一种解释和仍未确认的内容。

## 初始化新项目

先在会话中展示：

- 项目根目录；
- 缺少的固定目录；
- 缺少的 01/02 零字节占位文件；
- 已确认项目名称和课题目标；
- 不含占位符的 `PROJECT.md` 真实骨架草稿；
- 仍未知的信息；
- 保持不动的路径和本批排除工作。

新项目骨架必须：

- 填写真实项目名称、目标、目前主要做到、现在在做和时间；
- 保留 01–05；
- 01/02 保留固定小标题；
- 03 没有任务时写“暂无已登记的分析任务”；
- 04 没有任务时写“暂无已登记的图片任务”；
- 05 保留三个固定阶段但不展开虚构材料；
- 保留状态说明和取消记录；
- 不写尖括号占位符、示例任务或虚构路径。

用户批准完整批次后：

1. 运行 `scripts/create_project_directories.py <root> --apply`；
2. 仅在完整草稿获批时创建 `PROJECT.md`；
3. 验证目录、两个占位文件的零字节状态和 `PROJECT.md`；
4. 报告未执行事项。

## 接入进行中项目

先扫描并把真实工作映射到模板：

- 01/02 根据对应材料和已确认信息填写固定小项；
- 03 为每项真实分析建立同级任务块；
- 04 为每个真实 Fig 或图片建立同级任务块；
- 05 根据现有稿件、投稿和审稿材料展开；
- 取消内容保留在原位置并建立末尾索引。

必须区分：

- 已确认事实：用户明确说明或可靠材料直接证明；
- 推断：材料支持但尚未确认；
- 未知：当前无法可靠确定。

对于项目外、旧结构或位置不合适的材料，先按 [material-copy.md](material-copy.md) 在会话中规划。不得把推断伪装成事实，也不得为了套模板制造任务。

## 后来发现的新材料

材料接入不限于首次初始化。项目推进中发现新的历史文件、外部数据、合作者交付、旧结果或遗漏备份时：

1. 保持当前唯一项目根目录不变；
2. 只读扫描用户明确放入范围的来源；
3. 判断它属于 03、04、05、项目汇报，还是仅应作为证据供 01/02 的负责 skill 提炼；
4. 在会话中建立新的编号映射批次；
5. 明确列出包括和排除内容；
6. 用户批准后才复制；
7. 复制完成后重新评估 `PROJECT.md`，但不要自动写入。

不要自动扫描整台计算机，也不要把整个来源根目录默认纳入。

## 材料复制后的状态判断

复制成功只证明材料已经接入，不证明科研任务已完成。

- 有操作结果但尚未检查：通常标为待审计；
- 仍在运行、等待输入或存在版本冲突：通常标为进行中；
- 仅当工作和必要检查都完成且用户确认可依赖：标为已完成；
- 仅作为历史快照：登记为路径证据，不创建虚构分析任务；
- 明确取消的版本：保留原任务块和取消索引。

## 逐步长出任务块

后续讨论、工作或材料接入产生真实事项时：

1. 确定它属于 01–05；
2. 对 03/04 建立同级真实任务块；
3. 对 01/02/05 更新固定块，必要时才展开；
4. 填写事实、下一步、卡点、结果和真实路径；
5. 联动更新大标题和顶部摘要；
6. 展示精确修改并等待批准。

任务完成时只改状态和字段，不移动到“已完成”专区。取消时保留原块并建立索引。

## 同步 PROJECT.md

同步信息可以来自：

- 当前 `PROJECT.md`；
- 项目递归只读扫描；
- 当前对话和用户说明；
- 经验证的复制结果；
- 其他 skill 已确认结果；
- Git skill 已建立仓库时的相关只读状态。

一次同步必须展示所有联动修改：

- 具体任务和标题状态；
- 所属部分状态；
- 顶部“目前主要做到”“现在在做”“最近更新时间”；
- 下一步、卡点、结果和路径；
- 取消事项的原块和末尾索引。

不要加入未展示的顺手修改。文件时间只能作为证据，不能自动推翻用户明确说明。

## 读取状态和目录审计

只读解释当前主要进度、正在做的事项、下一步、卡点、待审计和取消事项。

如果项目材料与 `PROJECT.md` 冲突，展示具体冲突并请用户确认，不要静默选择时间更新的一方。

目录审计可以：

- 比较固定骨架；
- 规划缺失目录和 01/02 空占位文件；
- 规划并执行经批准的字节级复制；
- 为需要内容提炼的材料指出负责 skill。

目录审计不能移动、重命名、删除、覆盖、合并或改写材料。

## 批准和会话状态

批准必须对应已经展示的明确批次。部分批准只授权对应部分，沉默、含糊回复或切换话题不构成批准。

本 skill 开启后在当前 Codex 任务中持续有效，不再每轮询问是否关闭。用户明确关闭或显式调用另一个 skill 时，按 `SKILL.md` 的会话状态规则关闭。
