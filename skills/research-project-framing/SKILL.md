# 01 立项与选题论证

把尚在讨论中的项目想法收敛成“研究什么、为什么值得做、为什么有新意、准备大致往哪里做”的活立论。让输出足以指引 02 展开施工设计，但不要越界写成实验方案。

## 显式开启和会话状态

只在用户显式调用 `$research-project-framing` 时开启。不要隐式启动。

开启后：

1. 简短说明“01立项与选题论证已开启”。
2. 在当前 Codex 任务的后续多轮对话中持续保持开启，不再要求用户每轮重复调用。
3. 仅在后续请求仍属于本 Skill 边界时参与；话题暂时偏离 01 时不强行介入，但不因此关闭。

它不是后台程序。新的 Codex 任务默认关闭，必须重新显式调用。

只有以下两种情况关闭：

1. 用户明确要求关闭 `$research-project-framing`；
2. 用户显式调用另一个 Skill。

检测到用户显式调用另一个 Skill 时：

- 不再启动新的 01 讨论、检查、检索或写入动作；
- 已在运行的单个操作先到达安全边界，不强制中断正在写入的文件；
- 简短说明“01立项与选题论证已关闭”；
- 后续只按新 Skill 执行；
- 新 Skill 结束后不要自动重新开启本 Skill。

同一条消息同时显式调用本 Skill 和另一个 Skill 时，另一个 Skill 优先，本 Skill 保持关闭。普通聊天、工具调用、App 调用或其他 Skill 的隐式使用不构成关闭条件。关闭后，只有再次显式调用 `$research-project-framing` 才能重新开启。

## 先读取产品规范

在建立、检查或更新 01 前，完整读取 references/product-template.md。把其中的完全体结构、骨架态、生长规则和引用格式作为运行时产品规范。不要凭记忆重造栏目。

## 确定项目与输入

1. 确定项目根目录。没有可靠路径时先询问，不在猜测的目录写文件。
2. 检查根目录是否存在 01_立项与选题论证.md。
3. 同时识别可能等价的旧立项书、选题记录、开题前言、项目脑暴或零散论证材料。
4. 读取与当前任务直接相关的项目文件；其他文件保持只读。
5. 接受自然语言讨论作为一等输入，不要求用户先按模板整理。

已有规范文件是当前立论的内容源。自然语言中的最新明确决定可以更新它；未被用户选定的候选方向只能作为候选或论证记录，不能冒充当前方案。

## 区分讨论、检查与写入

- 讨论：梳理问题、推荐方向、指出缺口、提出检索与修改建议，不写任何文件。
- 检查：读取现有 01，报告缺口、冲突、证据不足和可改之处，不写文件，除非用户同时明确要求修改。
- 建立或更新：只有用户明确要求“创建、写入、更新、修改、整理进 01”等文件动作时才写入。仅调用本 Skill 不等于授权写文件。
- 精确写入请求本身可视为授权，不重复索要形式化确认。
- 涉及合并、迁移、覆盖等价材料，或需要移动、重命名、删除旧文件时，先展示映射和处理方案，等待用户单独确认；本 Skill 默认只维护规范文件，不处理旧文件。

## 执行工作流

### 1. 收拢当前问题

从用户讨论和已有材料中提取真正要回答的科学问题。把宽泛主题、研究对象描述、方法兴趣与核心问题区分开。可以提出候选表述并推荐，但不替用户拍板。

### 2. 建立立论链

按以下推理顺序组织，不按文献出现顺序堆叠：

现象或需求 → 已有认识 → 认识边界或矛盾 → 关键缺口 → 核心研究问题 → Novelty → 预期贡献

让每一步都能解释为什么自然地推出下一步。若尚未收敛，保留真实缺口，不用套话填满。

### 3. 检索和核对文献

允许并应在关键背景、已有认识、缺口和 Novelty 缺少依据时检索文献。

- 优先核对原始研究和全文；只能获得摘要时明确证据层级，不扩写摘要未支持的结论。
- 对最接近的已有工作做比较，避免只搜主题相似文献。
- 把支持关系写在相关论断旁边，格式遵循产品规范。
- 无论处于讨论还是写入，只要给出可能进入 01 的背景、缺口或 Novelty 表述，就使用“年份｜期刊｜第一作者姓｜支持：具体发现及其支持关系”的格式；网页链接只能补充，不能替代该支持说明。
- 区分文献原结论与本项目推断；推断明确写“据此推断”。
- 文献冲突时并列研究条件和适用边界，不强行合并。
- “没有检索到”不能写成“从未有人研究”；首次、唯一、空白等强断言使用高门槛。
- 当新增检索不再改变核心判断时停止，并说明尚未覆盖的范围。
- 不修改正式引文或参考文献，不读写 Zotero，不把 PDF 或文献库复制进项目。

若用户只要求查文献，完成检索与讨论即可；除非用户明确要求，不创建或更新 01。

### 4. 形成故事雏形

把初步研究构想写成策略层桥接：说明准备大致往哪个方向做、需要哪类证据把故事立住。保持散文表达，不引入板块号、证据号、数据号、单图号、Fig 号或可直接开工的方法流水线。

### 5. 维护当前立论与论证记录

- 当前采用的立论位于文件前部，随用户最新明确决定就地更新，只保留当前版。
- 被否决、搁置或作为备选的方向追加到“论证记录 / 已放弃”。
- 保留原方向、未采用原因、已有依据和重新启用条件，避免以后重复走弯路。
- 重新启用时保留旧记录并更新状态；只有用户明确决定采用后，才让它覆盖当前立论。

### 6. 写入并核查

写入时只创建或维护项目根目录的 01_立项与选题论证.md。完成后检查：

- 核心研究问题是否能用一段连贯的话说清。
- 已有认识是否真正导向关键缺口。
- 缺口是否有文献边界，而不是由“没搜到”推成。
- Novelty 是否相对最接近的已有工作成立。
- 预期贡献是否由核心问题的回答推出。
- 初步研究构想是否足以指导 02，又没有进入施工层。
- 关键背景、缺口和 Novelty 是否能回到具体来源。
- 被否方向是否与当前采用方案区分清楚。

## 中途项目与等价材料

发现两个或更多候选材料时：

1. 列出每份材料对应产品模板的哪些部分。
2. 标明重复、冲突、过期和只有一处出现的内容。
3. 推荐如何合并为根目录单文件，并说明旧结构的处理建议。
4. 等待用户确认后再建立或更新规范文件。
5. 未获授权时允许旧结构暂时存在，但不要另建第二套规范文件。

## 边界

只维护 01_立项与选题论证.md。不要：

- 编写带编号的故事板块、证据、数据、单图、Fig 或技术路线阶段。
- 执行数据分析、生成实际结果图、制作图版或撰写论文正文。
- 修改 PROJECT.md、进度状态、导师意见库或其他项目文件。
- 自动调用或修改 02；只把 01 形成的研究问题、立题依据、Novelty 和故事雏形交给后续设计。

没有 01 的中途项目可以直接做后续工作；不要以补齐历史为由阻塞用户。
