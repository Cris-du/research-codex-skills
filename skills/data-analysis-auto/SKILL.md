# data-analysis-auto（03 数据分析 · 唯一全自动入口）

## 角色与唯一流程

本 skill 负责当前项目中任意规模的数据分析和已有任务修订。它不按输入单元数量、脚本数量或任务复杂度分流，也不设置任何小规模上限。

默认端到端流程固定为：

`解释准入 → 自动规划 → 任务说明与规划表 → 参数化源码 → 正式运行 → 独立复现 → 新输出解释同步 → 工作流日志`

它只与 `data-analysis-explanation` 联动。解释体系由 explanation 负责；本 skill 不直接创建、补写或修改解释汇总表、txt 解释文件和隐藏同步记录。

## explanation 加载契约

进入输入准入、授权修复或新输出同步前，必须从当前 `SKILL.md` 所在目录的父目录解析并完整读取：

`../data-analysis-explanation/SKILL.md`

不得凭名称、旧会话记忆或本文件中的摘要代替其完整规则。目标不存在、不可读或 frontmatter 名称不匹配时安全停。本 skill 只负责提供明确模式和范围：

- `preflight-audit`：本次输入的只读准入。
- `authorized-repair`：用户已明确指定对象、动作和范围后的解释修复。
- `new-output-sync`：复现通过后，本次新增或语义变化输出的定向同步。

## 触发与边界

在能够唯一解析 `$ResearchProjectsRoot` 的科研项目环境中，用户要求使用当前项目数据或单元库做清洗、筛选、合并、统计、建模、相关性、差异分析、结果表、数据驱动绘图、正式重跑或已有任务修改时使用本 skill。用户显式调用 `$data-analysis-auto`、全自动数据分析或完整 03 分析流程时同样使用。

以下请求不使用：

- 用户明确要求普通 Codex、非 skill 化工作台、不走单元库或不要 03 数据分析流程。
- 02 的科研问题论证、实验设计和技术路线设计。
- 04 的图版选择、物理拼版、A/B/C/D 组合和排版。
- 只解释统计概念、方法原理或已有文字，不执行项目数据任务。

激活状态只在当前会话有效，不写入文件，也不从历史规划表、日志或会话总结自动恢复。用户只要求本次旁路时仅旁路本次；用户明确关闭本流程时，直到再次显式启用前不自动恢复。

## 可配置项目根与持久路径

`$ResearchProjectsRoot` 表示“包含一个或多个科研项目目录的父目录”，不要求它具有固定名称。按以下优先级解析：

1. 用户在当前任务中明确给出的目录。
2. 环境变量 `RESEARCH_PROJECTS_ROOT` 指向的现有目录。
3. 当前路径位于固定项目骨架内时，定位最近的 `03_数据与分析` 祖先目录，并把项目目录的父目录作为 `$ResearchProjectsRoot`。
4. 否则只在当前打开的项目或工作区内部寻找唯一符合固定项目骨架的候选；禁止扫描整台电脑、其它盘符、用户目录或同步盘根。

找不到、找到多个候选或配置目录不存在时安全停，请用户确认。不要把某个开发者的盘符、用户名、同步盘名称或目录名当作默认值。

规划表、解释体系、日志和持久路径清单只保存 `$ResearchProjectsRoot` 之后、以项目名开头的项目相对路径。运行时才把 `$ResearchProjectsRoot` 与项目相对路径拼接成当前电脑可用的绝对路径。

当前项目工作记录根固定为：

`<项目名>\03_数据与分析\skill化工作记录`

## 新建与微调路由

在任何写操作前，先按语义解析肯定、否定和保留旧版要求，再按以下优先级确定 `TASK_MODE`。

### 1. 明确新建：直接 `NEW_TASK`

用户明确肯定要求“新建”、新任务、新时间戳、另做一版、保留原版、不要覆盖原结果或等价表达时，不询问是否微调，直接创建新的分钟时间戳任务。若同一句同时出现“微调”和“新建/保留原版”，新建意图优先。

### 2. 明确微调：直接 `IN_PLACE_REVISION`

用户肯定使用“微调”二字，且没有否定该意图、没有要求新建或保留原版时，不再询问是否原地修改，直接进入微调。若当前会话或用户路径能够唯一确定历史任务，立即冻结该任务；若不能唯一确定，只询问具体目标目录，不再询问是否微调。

### 3. 明显普通新任务：直接 `NEW_TASK`

请求没有指向已有时间戳、旧图表、旧源码、旧参数或旧正式输出，且明显要求开展新分析时，直接新建，不额外询问。

### 4. 未说微调但语义像修改旧任务：询问一次

用户未明确说“微调”，但请求指向上次、原来、这个已有图表、某个时间戳、旧脚本、旧方法或旧参数并要求修改时，只问一次：

> 我判断这是在修改已有时间戳任务。是否按原时间戳微调并覆盖更新？如果不是，我会新建分钟时间戳处理。

回答原地修改时进入 `IN_PLACE_REVISION`；回答不是、要求保留原版或要求新建时进入 `NEW_TASK`。同一独立请求确认后不再重复询问。

### 5. 否定与冲突

- “不要微调，直接新建”是 `NEW_TASK`。
- “不要新建，就在原任务微调”是 `IN_PLACE_REVISION`。
- “这不是微调，是新任务”是 `NEW_TASK`。
- 无法判断最终肯定意图时，只询问一次路由，不猜测。

进入 `IN_PLACE_REVISION` 后必须完整读取 `references/revision.md`。明确说“微调”只授权修改能够唯一归属于目标分钟任务的受影响内容，不授权修改其它时间戳、其它项目、主单元库或共享模板原件。

## reference 读取路由

- 每个任务在解释准入 PASS 后、形成规划前，完整读取 `references/planning/规则索引.md` 及其要求的规则。
- 写业务源码、复制 PS1、运行、复现和写日志前，完整读取 `references/execution/脚本与重跑规则.md`。
- `IN_PLACE_REVISION` 还必须完整读取 `references/revision.md`。
- 生成 PS1 前读取两个固定 PS1 reference；含 R 时再读取固定 R 运行时选择 reference。

reference 是详细实现来源。本文件只保留统一状态机和不可绕过的跨阶段硬规则。

## 统一状态机

### 1. 确定任务和输入范围

定位当前项目，保留用户原始任务，确定候选输入、预期输出和 `TASK_MODE`。默认只处理本次任务涉及的输入和输出，不扩大到全库或其它历史任务。

### 2. explanation 只读准入

对新任务的全部输入执行 `preflight-audit`。历史微调先读取原任务说明、规划表、业务源码、日志和受影响单元解释；新增输入、替换输入或既有解释不足以支撑修改时，对相应范围执行 `preflight-audit`。

返回契约必须包含：

- `PRECHECK_STATUS`：`PASS`、`MISMATCH`、`NEEDS_USER` 或 `BLOCKED`。
- `TASK_SCOPE`。
- `INPUT_UNITS`。
- `DIFFERENCES`。
- `QUESTIONS`。

只有 `PASS`、`DIFFERENCES=none` 且 `QUESTIONS=none` 才允许继续。非 PASS 时在会话报告并停止；不得创建新任务目录、规划表或业务源码。用户明确授权修复后，以 `authorized-repair` 只修改指定对象和范围，再对同一范围重新准入。只有最新结果 PASS 才放行。

### 3. 冻结目录身份

`NEW_TASK` 在准入 PASS 后创建：

`<工作记录根>/<YYYYMMDD>/<HHMM>_<主题>[_序号]/`

同一分钟同主题重名时追加 `_02`、`_03`。本次固定输出时间戳为 `YYYYMMDD_HHMM`。

`IN_PLACE_REVISION` 不创建新日期或分钟目录。必须冻结：

- `TARGET_TASK_ROOT`：原完整分钟叶目录。
- `TARGET_DATE_ROOT`：其直接父日期目录。
- `TARGET_RESULT_ROOT`：同一日期下的 `结果`。
- `TARGET_EXPLANATION_ROOT`：同一日期下的 `结果/解释`。

目标必须位于当前项目工作记录根内，并匹配 `YYYYMMDD/HHMM_主题[_序号]`。禁止用裸分钟、裸脚本名或其它时间戳中的同名文件建立替代映射。

### 4. 自动完整规划

规划表必须细到业务源码无需重新猜测：输入单元、字段、工作表、匹配键、统计单位、筛选、NA/0/重复值、转换、方法、阈值、输出角色、落库位置、脚本数量、顺序、依赖、参数、输出名和复现策略全部明确。

规划表仍使用既有统一列结构，两个确认列写 `全自动规划`。本流程不进行例行逐行人工确认。关键科研口径、方法、输出角色、路径或覆盖范围确实无法确定时才集中询问；得到答案后更新同一规划继续。

自动规划完成后生成唯一 `任务说明.md`，只用自然语言记录科研目标、核心对象、关键口径与方法、预期结果和主要边界，不复制规划表，不写 PS1、绝对路径、运行结果或复现细节。

### 5. 生成并执行

严格按规划表写参数化 Python/R 业务源码。数据分析、统计、结果表、绘图输入和结论数字由 Python 生成；最终绘图由 R 完成。所有业务输入输出通过命令行参数传入，不在业务源码中写死电脑路径。

随后按固定 reference 生成并运行：

1. `run_pipeline.ps1`
2. `reproduce_pipeline.ps1`

第二个 PS1 只生成客观复现记录；本 skill 读取 `复现哈希记录.txt` 并按规划表判断。正式运行或复现失败时安全停，不进入新输出解释同步。

### 6. explanation 同步新输出

复现判断通过后，把本次新增或语义变化输出的项目相对路径清单交给 explanation，模式固定为 `new-output-sync`。只同步明确清单，不扫描或重写无关历史解释。

纯字体、颜色、背景、图例位置、画布或分辨率微调如果没有改变图形科研含义，仍读取相关解释核对语义，但交接 `NO_SEMANTIC_CHANGE`，不修改解释汇总表或 txt。表头、字段含义、方法、口径、统计结果、输出结构或图形科研含义变化时必须定向同步。

### 7. 写日志并返回

最后写 `工作流日志.txt`，记录项目相对路径、任务模式、准入结果、规划、业务源码和顺序、正式运行、R 环境、复现判断、新输出清单、解释同步、微调变更轨迹和安全停。日志只供人读，不作为 PS1 的机器输入。

## 绝对单图规则

所有图形输出实行：

`一个 PDF = 一页 = 一个主要数据面板 = 一个独立科研图形`

对应 TIF 必须是同一单图，300 dpi。该规则不可被用户在 03 分析任务中的拼接要求解禁；需要多个图时，必须输出多个独立的 PDF/TIF 文件对。

禁止拼接、多面板、分面、A/B/C/D、上下或左右组合、主图加 inset、主图加边际数据图、多个独立坐标面板、多页 PDF、多帧 TIF，以及通过 R 组合包、多个 `print()`、图形设备、grob、viewport 或其它方式把多个数据图放进同一文件。一个 R 对象只要视觉上含多个数据面板，同样违规。

标题、坐标轴、图例、色标、文字标签、显著性标记、参考线、回归线、置信区间和同一坐标系内的多个数据层可以保留；它们不得形成第二个独立数据面板。

规划、模板选择、R 源码和最终文件必须四层检查。组合模板不合格；能可靠拆成多个独立输出时拆分任务复制件，否则改用单图模板或新写单图 R 脚本。违反单图规则时不得标记成功、不得进入解释同步。

## 固定产物结构

每日结构保持：

```text
YYYYMMDD/
├── 结果/
│   ├── 单元库/
│   │   ├── 信息单元库/
│   │   └── 图文单元库/
│   │       ├── 文/
│   │       └── 图/
│   └── 解释/
└── HHMM_任务主题[_序号]/
    ├── 任务说明.md
    ├── 规划表.xlsx
    ├── 规划表列出的正式业务源码
    ├── run_pipeline.ps1
    ├── reproduce_pipeline.ps1
    ├── 复现哈希记录.txt
    └── 工作流日志.txt
```

新输出不得直接写回用户提供的主单元库。时间戳叶目录最终不得遗留规划辅助脚本、解释同步脚本、缓存、中间表、调试文件、`__pycache__`、规划表导出副本或 `test`。无法清理时安全停并写入日志。

## 安全停

以下情况不猜测、不扩大范围：

- 当前工作区无法唯一定位锚点或当前项目。
- explanation 不可读或输入准入不是 PASS。
- 新增或替换输入尚未重新准入。
- 科研目标、统计口径、方法、输出角色或路径存在关键歧义。
- 明确微调但目标分钟目录不能唯一确定。
- 微调会越出目标任务或影响其它任务、主库、共享模板原件。
- 新任务或未授权请求会覆盖已有正式输出。
- 规划表缺少业务源码执行所需关键内容。
- R 环境不可用、R 绘图失败或只能通过组合图实现。
- R 源码或最终文件违反绝对单图规则。
- 正式运行、测试分支或复现判断失败。
- 实际落库角色与规划或解释体系规则冲突。
- 必须扩大用户授权范围才能继续。

本 skill 不引用、不检查、不调用用户自己的备份、核对或验证工具。
