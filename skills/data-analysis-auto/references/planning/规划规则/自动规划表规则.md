# 自动规划表规则

## 总要求
`NEW_TASK` 必须生成自动版 `规划表.xlsx`。它不是用户确认版规划表，用户不需要修改；但它是本次脚本和输出的执行边界。规划表沿用既有统一结构，不能因为是全自动模式就简化。确认后的原地微调按下述例外复用原规划表。

规划表使用一个主工作表，一次性写完整任务框架和具体操作流程。统一列为：

`序号 | 任务 | 输出角色 | 落库位置 | 输入 | 依赖 | 科研意图 | 口径与参数 | 预期输出内容 | 输出解释要点 | ❓ | 你确认(任务框架) | 语言 | 脚本名 | 脚本逻辑 | 输入根目录 | 输入子目录或文件 | 输出名 | 输出根目录 | 输出子目录或文件 | 复现比较策略 | 你确认(操作流程)`

两个确认列写 `全自动规划`。如果存在需要用户拍板的关键口径、方法、输出类型或路径，本 skill 必须安全停，不能把不确定项伪装成自动确认。

完整自动规划表确定后、写业务脚本前，生成同一时间戳叶目录唯一的 `任务说明.md`。它不是规划表的 Markdown 副本，只把最终自动规划改写为连贯的自然语言，说明本次最终要完成的科研目标、核心分析对象、关键口径与方法、预期结果和主要边界。文件只使用 `# 任务说明` 和正文，不加入逐行任务表、固定路径清单、脚本参数、PS1 命令、复现策略、R 环境或运行结果；内容不足以准确说明任务时安全停。

## 历史任务微调例外
上述新建规划表和任务说明规则只适用于 `NEW_TASK`。`IN_PLACE_REVISION` 的识别、优先级、目标冻结和授权边界必须先完整读取 `references/revision.md`；本文件不得重新询问“是否微调”或改变已经确定的任务模式。原地微调读取并复用目标分钟时间戳叶目录唯一的 `规划表.xlsx`、`任务说明.md`、业务脚本、两个 PS1、复现记录和日志，不创建任何版本副本。

微调是否更新规划表取决于用户要求是否改变规划事实，而不是改动大小。纯字体、颜色、背景、图例、画布、分辨率等表现层调整不改规划表；表头、输出结构、输入、筛选、分组、方法、阈值、统计、脚本数量/顺序/依赖、输出路径或比较策略变化时，原地更新受影响行并保持整表自洽。用户对本次微调的确认就是原地修订授权，两个确认列继续保留 `全自动规划`，不再次逐行确认。

只有科研目标、核心方法、关键口径、预期结果或主要边界变化时才同步覆盖更新原 `任务说明.md`；纯表现层、显示表头、导出格式或不改变科研含义的实现修正不改任务说明。微调完成后，规划表、任务说明、脚本、正式结果、解释和日志必须描述同一个修订后任务。

## 任务框架部分
每一行必须写清：

- `任务`：本步具体回答什么科研问题。
- `输出角色`：只允许 `基础数据`、`分析结果`、`图形结果`。
- `落库位置`：只允许 `信息单元库`、`图文单元库/文`、`图文单元库/图`。
- `输入`：使用哪些单元、文件、工作表、字段、行列范围、分组、对象和匹配键。
- `依赖`：依赖哪些前序输出；每个 R 绘图步骤都必须依赖此前由 Python 在本次结果中生成的专用绘图输入文件。
- `科研意图`：本步回答的科研问题、分析对象和判断目标。
- `口径与参数`：统计单位、筛选范围、阈值、NA/0/重复值处理、标准化/转换、统计方法、p 值、q 值、多重校正、排序和显著性判断。
- `预期输出内容`：将来能获得什么内容，并写明解释体系单元类型。
- `输出解释要点`：交给 explanation 写解释体系时需要说明的来源、方法、结果口径、字段含义、图形元素含义和结论方向。
- `❓`：若有会影响结果正确性的不确定项，必须写明并安全停。

## 输出角色和单元类型
先判断内容角色，再决定落库位置和解释体系单元类型：

- 基础数据 → `信息单元库`，写明信息单元类型1/2/3/4。
- 分析结果 → `图文单元库/文`，写明图文单元类型3/4。
- 图形结果 → `图文单元库/图`，写明图文单元类型1/2。

判断依据是内容，不是扩展名。相关性结果、显著性表、模型结果、统计汇总和绘图输入表即使是 `.tsv`、`.csv` 或 `.xlsx`，也不得默认放进信息单元库。正式保留的绘图输入表统一进入 `图文单元库/文`，解释为 `类型4 · 单个表格单元`。

用户未指定输出类型时，本 skill 必须自行判断并在规划表中写明理由。用户明确指定输出类型或落库位置时，按用户指定；若明显冲突，必须安全停并说明冲突，不能擅自覆盖用户意图。

## 具体操作流程部分
每个脚本步骤必须写清：

- `语言`：数据分析、清洗、筛选、合并、统计、建模、结果表和绘图输入表强制 Python；最终绘图强制 R。
- `脚本名`：与运行顺序一致。
- `脚本逻辑`：读取、筛行、筛列、join、NA/0/重复值处理、计算、排序、写出结果和绘图输入表；R 行写清只读取绘图输入表并完成绘图层处理。含 R 绘图时，还必须写明共享模板的项目相对来源、`原样复用`/`微调复用`/`新写R脚本`、复制后的任务脚本名、完整参数接口、允许微调范围和 PDF/TIF 输出；模板来源是代码来源，不得写入业务输入路径列。每个绘图输出行只允许对应一个独立主图及其一对 PDF/TIF 文件；多个图必须拆成多行和多对文件。
- `输入根目录`：历史输入写 `$ResearchProjectsRoot` 之后、以项目名开头的主单元库项目相对根路径；本次上游输出写同样格式的本次结果单元库项目相对根路径。不得写盘符、用户名或电脑同步根。
- `输入子目录或文件`：输入在根目录下的相对路径或具体文件名；必须写清工作表、列、行、过滤条件和 key。
- `输出名`：将要落库的唯一输出名称。
- `输出根目录`：写 `$ResearchProjectsRoot` 之后、以项目名开头的每日 `工作记录目录/YYYYMMDD/结果/单元库` 项目相对根路径；不得把新输出写入用户提供的主单元库。
- `输出子目录或文件`：必须包含科研主题子目录和具体文件名；图输出必须同时记录 PDF 主文件和 TIF 300 dpi 备用图。
- `复现比较策略`：非图形输出写 `strict_hash`；PDF/TIF 等图形输出写 `loose_visual`；目录输出写 `auto_by_extension`。

规划表的脚本行只能是正式分析脚本、绘图脚本和必要格式转换脚本。不得把规划表生成、规划表检查、日志生成、解释同步、缓存整理或临时辅助脚本写成执行步骤，也不得让两个 PS1 调用这些辅助脚本。自动规划阶段必须确定全部脚本数量、顺序、依赖、输入、输出和参数；执行阶段只把这些业务命令机械填入固定 `run_pipeline.ps1` reference 的规划命令区。`test/单元库` 由模板的 `-TestMode` 自动从正式结果结构派生，不进入规划表，也不更改文件名。

## 语言分工硬规则
Python 强制负责所有数据分析和结果生成，包括数据读取、清洗、筛选、合并、排序、统计、建模、p 值、q 值、结果表、绘图输入表和结论文本中的数字判断。

R 强制负责最终绘图。R 只能读取 Python 在本次 `结果/单元库/图文单元库/文` 生成的专用绘图输入文件，设置因子顺序、颜色、图例、字体、画布和导出格式；不得直接读取信息单元库、图文单元库、其它库、历史结果或普通分析结果，也不得重新计算核心统计结果、重新决定显著性或改变 Python 已确定的结果口径。

含 R 行时，本 skill 固定检查 `$ResearchProjectsRoot\绘图模式脚本库`，按科研意图、图形语法、专用绘图输入结构和输出规格选择模板，并完整遵守 `输出目录与图形拆分规则.md`。自动规划表只记录类似 `绘图模式脚本库\热图绘制\热图_参数输入模板.R` 的相对来源，并写明运行时固定读取 `绘图模式脚本库\Rscript_exe.txt` 与 `绘图模式脚本库\R.txt`。现有模板和新写 R 脚本统一保留 `--r-lib-file` 接口；不得记录候选文件中的某一行、任一电脑的 Rscript/R 包库绝对路径或电脑专用 TXT。任何模板若会生成分面、拼接、嵌套、边际图、多页 PDF 或一次写出多个主图，都不得选用；多个模板会产生不同科研表达时必须安全停。

即使既有文件已经可以直接绘图，也必须自动规划一个 Python 前置步骤完成读取、结构校验和本次专用绘图输入输出。该专用文件必须单独列为正式输出、标记 `strict_hash`，并成为 R 行的直接输入；不允许通过手工复制或只改路径名完成。缺少该步骤时本 skill 必须安全停。

不允许 Python 绘图兜底。R 绘图失败时，应修 R 脚本；无法修复则安全停。

## 泛化描述判定
任务框架中只要没有说明对象、输入、输出角色、落库位置、单元类型、科研意图、统计单位、计算口径、方法、参数、输出含义或判断标准中的必要部分，就视为泛化描述。

具体操作流程中只要没有说明脚本操作、输入根目录、输入子目录或文件、使用行列、匹配键、筛选规则、输出名、输出根目录、输出子目录或文件、比较策略中的必要部分，就视为泛化描述。

泛化描述不能进入自动执行；必须具体化，否则安全停。
