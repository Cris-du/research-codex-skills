# 输出规格与脚本复现规则

## 目的
自动规划阶段必须写清将来能获得的具体内容、每个文件的落库位置、每个脚本的参数调用方式，以及正式运行和复现运行的区别。

## 所有结果必须脚本化
凡是会改变、筛选、提取、计算、排序、合并、重命名、统计、绘图、写结论或生成输出文件的操作，都必须规划为脚本步骤，并由本 skill 实际运行脚本得到最终文件。

禁止规划任何需要手动提取、手动筛选、手动复制、手动编辑、手工计算、手工改图、手工填写结果数字或手工写带结果判断文本的步骤。禁止先人工得到中间结果，再让脚本接着处理；也禁止让脚本复刻人工已经得到的结果。

## 参数化脚本规划
所有 Python/R 脚本都必须规划为命令行参数调用。脚本内部不得写死业务输入路径或业务输出路径。不同脚本可以有不同参数名，但输入文件、输出文件、绘图输入表、颜色表、注释表、PDF/TIF 输出等关键路径必须通过参数显式传入。

## 共享 R 绘图模板规划
含 R 绘图时，先检查环境变量 `RESEARCH_PLOT_LIBRARY_ROOT` 指向的可选共享绘图库；未设置时，仅在 `$ResearchProjectsRoot/绘图模式脚本库` 实际存在时把它作为兼容候选。若有模板库，先按图类型缩小到候选目录，再阅读模板参数定义、`--help` 内容和必要测试输入表头；测试输入只用于理解接口，不得成为正式任务输入。根据科研意图、图形语法、专用绘图输入结构和输出规格自动选择：

- `原样复用`：模板接口和绘图行为已满足规划。
- `微调复用`：科研含义不变，只调整参数接线、列映射、因子顺序、规划指定的颜色/文字/画布或补齐 PDF/TIF 输出。
- `新写R脚本`：没有合适模板，或继续修改会改变模板的图形逻辑和科研表达。

共享绘图库缺失本身不构成安全停；此时直接走 `新写R脚本`。不得引用开发者机器上的私有模板路径。

自动规划表在 R 行的 `脚本逻辑` 中记录模板相对来源、复用方式、任务脚本名、专用绘图输入、完整参数、允许微调范围和输出，不新增模板专用列。多个候选模板会产生不同科研表达时安全停。新写 R 脚本必须支持 `--help`、`--r-lib-file`、显式输入和显式 PDF/TIF 输出，不得写死电脑或项目路径。

自动规划表不解析或持久化当前电脑的 R 环境，只写明 `run_pipeline.ps1` 每次运行时按 `RESEARCH_RSCRIPT`、可选共享绘图库中的 `Rscript_exe.txt`、当前 `PATH` 中的 `Rscript` 依次选择第一个能够通过 `--version` 的候选。共享绘图库存在 `R.txt` 时通过 `--r-lib-file` 传给兼容模板；不存在时使用 R 自身标准包库配置。不得保存候选文件中的某一行、实际选中的机器绝对路径或电脑专用 TXT；运行时没有可用 Rscript 时安全停。

## run_pipeline.ps1
必须把固定 `run_pipeline.template.ps1` 复制到分钟时间戳叶目录并命名为 `run_pipeline.ps1`，把它作为正式运行事实脚本。正式产出结果时必须实际运行该脚本，不能先手动运行单个 Python/R 脚本再事后补总脚本。

规划阶段必须确定全部脚本数量、运行顺序、上下游依赖、输入、输出和完整参数，使执行阶段能够机械填写模板的规划命令区。`run_pipeline.ps1` 只调用规划表明确列出的正式分析脚本、绘图脚本和必要格式转换脚本，不在执行阶段推断前后依赖。

规划表中的持久路径固定写 `$ResearchProjectsRoot` 之后、以项目名开头的项目相对路径，不得写盘符、用户名或电脑同步根。模板运行时优先使用显式参数或环境变量 `RESEARCH_PROJECTS_ROOT`，否则从固定项目骨架推导 `$ResearchProjectsRoot`；再用 `$DailyRoot` 和 `$OutputBranch` 在正式 `结果` 与复现 `test` 间切换。自动规划只负责给出各业务命令所需的相对子路径，不另外设计路径框架。

规划时禁止把规划表生成、规划表检查、日志生成、解释同步、缓存整理或临时辅助脚本放入任一 PS1。输出父目录默认由对应 Python/R 脚本内部创建。`run_pipeline.ps1` 不负责解释体系维护，不读取工作流日志，也不调用 `reproduce_pipeline.ps1`。

## reproduce_pipeline.ps1
不为 `reproduce_pipeline.ps1` 规划第二套命令。直接把固定 reference 逐字复制到分钟时间戳叶目录；它调用同目录的 `run_pipeline.ps1 -TestMode`，自然复用同一批输入、业务脚本、顺序、依赖和参数，把每日输出分支从 `结果` 切换为 `test`。

固定脚本递归遍历 `test` 中实际生成的文件，按相同相对路径定位 `结果` 中的正式文件，把双方存在性、大小和 SHA256 写入分钟时间戳叶目录的 `复现哈希记录.txt`，记录成功后删除 `test`。

正常流程必须在正式 `run_pipeline.ps1` 成功后立即运行 `reproduce_pipeline.ps1`。第二个 PS1 只取证，不保存任务输出清单或比较策略，也不判断通过；本 skill 读取记录并按自动规划表判断，通过后才调用解释 skill 的 `new-output-sync`。

## 复现比较策略
规划表必须为每个最终输出写清 `复现比较策略`，供本 skill 在读取 `复现哈希记录.txt` 后判断；策略不得写入第二个 PS1。

- `strict_hash`：用于表格、文本、统计结果、Excel、JSON、HTML 等非图形输出。正式输出和复现输出必须存在，文件大小和 SHA256 必须一致。
- `loose_visual`：用于 PDF、TIF、SVG、PNG、JPG 等图形输出。正式输出和复现输出必须存在、扩展名一致且非空，允许哈希不同。
- `auto_by_extension`：用于目录输出。必须比较相对路径集合；目录内非图形文件按 `strict_hash`，图形文件按 `loose_visual`。

## 图文单元输出规格
分析结果表、绘图输入表、结论文本等正式保留的文类结果进入 `图文单元库/文`。每个图形都必须先由 Python 在本次结果中生成专用绘图输入文件；即使已有库文件可以直接绘图，也必须经 Python 读取、校验并重新输出，不得让 R 直读既有文件。绘图输入表统一解释为 `类型4 · 单个表格单元`，标记 `strict_hash`，并写清它服务于哪个图、每行对应哪个绘图观测或图形元素、每列对应哪个坐标值、分组、标签、排序、统计结果或视觉编码。

图形结果进入 `图文单元库/图`。必须完整读取并遵守同目录的 `输出目录与图形拆分规则.md`。每个单个图单元默认输出同名两种格式：

- PDF 主文件。
- TIF 备用图，300 dpi。

备用图不再默认 PNG。除非用户明确另有要求，本套流程固定使用 PDF + TIF。

一个 PDF 必须恰好是一页、一个独立主数据图形面板；对应 TIF 必须是同一个单图。禁止任何分面、拼接、嵌套、边际图、共享画布、多页 PDF、同一图形设备多次打印、多个 grob 或多个 viewport。即使用户要求组合图，也必须拆成多个独立 PDF/TIF 文件；03 模块不承担物理拼版。

## R 绘图规格
最终绘图强制由 R 脚本生成。R 脚本只能读取 Python 在本次 `结果/单元库/图文单元库/文` 生成的专用绘图输入文件，不得直接读取信息单元库、其它库、历史结果或普通分析结果，也不得重新计算核心统计口径。

规划图形输出时必须写清图类型、横轴、纵轴、图形元素含义、图注项目、输入绘图表、输出 PDF、输出 TIF、TIF 300 dpi、画布宽高、字号、Nature 风格和低饱和度配色。每个规划行和每个 R 输出只能对应一个独立主图；多个图必须拆成多个规划行、多次独立导出和多对 PDF/TIF 文件。

画布必须偏大，宁可留白也不要截断标题、图例、坐标轴文字、热图行列名或标签。字体必须显式设置且清楚可读，不能依赖 R 默认小字号。

## 禁止泛化规划内容
禁止只写“分析数据”“做统计”“画图展示”“输出结论”“使用合适方法”“放到结果目录”。必须改写为具体对象、输入、行列、口径、方法、参数、输出文件、图形样式、脚本命令和比较策略；无法确定时安全停。
