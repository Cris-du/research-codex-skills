# 脚本与重跑规则

## 已确定任务模式
执行本文件前，必须已经按主说明与 `references/revision.md` 唯一确定 `TASK_MODE` 和目标目录。本文件不得重新询问“是否微调”、重新创建时间戳或改变目标。`NEW_TASK` 使用新分钟时间戳；`IN_PLACE_REVISION` 复用并覆盖更新唯一的原分钟时间戳任务，不创建 `_v2`、`_new`、`_style` 等版本副本。

原地微调优先修改原业务脚本；规划事实改变时原地更新规划表，科研目标、核心方法、关键口径、预期结果或主要边界改变时原地更新任务说明。微调按影响范围执行：

- 纯 R 表现层修改且输入、变量映射、统计、参数接口和输出路径不变：原地修改 R，按原参数直接运行 R 生成正式 PDF/TIF；该次修改成功后立即运行原第二个 PS1，不再请求第二次确认。
- 表头、输出结构、数据处理、筛选、分组、方法、阈值、统计、绘图输入或下游依赖变化：更新原规划和受影响脚本，必要时更新原第一个 PS1 的规划命令区；运行原第一个 PS1 正式模式，再运行原第二个 PS1。
- 微调不允许手工编辑正式结果；正式数据、表格、文字和图始终由修订后的业务脚本生成。纯样式以外的修改必须覆盖全部受影响下游，不能留下新旧口径混合结果。

## 脚本规则
所有会影响结果的操作必须由脚本完成并实际运行，包括读取、清洗、筛选、提取、合并、重命名、排序、计算、统计、绘图、写文和输出文件生成。

禁止手工提取、手工筛选、手工复制、手工编辑结果、手工计算、手工改图、手工填写结果数字或手工写带结果判断的文本。禁止先人工得到中间结果，再让脚本接着处理；也禁止脚本只是复刻人工已经得到的结果。

所有 Python/R 分析脚本必须通过命令行参数接收业务输入和业务输出路径。脚本内部不得写死本次任务的输入输出路径。不同脚本可以有不同参数名，但关键输入、关键输出、绘图输入表、颜色/注释表、PDF/TIF 输出必须显式传参。

脚本必须可复核：

- 文件前端用中文注释说明目的和功能。
- 参数读取区写清每个参数是什么、是否只读、产出用途是什么。
- 关键计算、统计、绘图、写文代码块写中文注释。
- 变量名尽量使用小写风格。
- 文本结论中的数字、方向判断和统计判断必须由 Python 脚本生成。

## 语言分工
数据分析强制 Python。Python 负责读取、清洗、筛选、合并、排序、统计、建模、p 值、q 值、结果表、绘图输入表和结论文本中的数字判断。

最终绘图强制 R。R 只读取 Python 准备好的绘图输入表，负责因子顺序、颜色、图例、字体、画布、PDF 和 TIF 输出。R 不得重新计算核心统计结果，不得重新决定显著性，不得重新改变 Python 已确定的结果口径。

不允许 Python 绘图兜底。R 绘图失败时必须修 R；修不了就安全停。

## R 绘图脚本要求
自动规划表指定共享模板时，沿用 `$ResearchProjectsRoot` 从 `$ResearchProjectsRoot\绘图模式脚本库` 找到模板相对路径，验证后复制到分钟时间戳叶目录并按规划表命名。只修改和运行复制件，不得修改共享模板原件、使用模板测试输入作为正式数据、在执行阶段换模板或把新写脚本自动加入共享库。复制时记录模板来源相对路径和源文件 SHA256。

严格执行 `原样复用`、`微调复用` 或 `新写R脚本`。微调只允许参数接线、输入列映射、因子顺序、规划指定的视觉编码、文字、字体、画布、PDF/TIF 输出和输入输出校验；不得改变筛选、样本排除、标准化、统计检验、p/q 值、显著性阈值、坐标科学含义、图类型或科研问题。必须改变这些内容时安全停。

现有模板和新写 R 脚本统一使用 `--r-lib-file`。新写脚本还必须支持 `--help`、显式绘图输入参数和显式 PDF/TIF 输出参数，不得写死电脑、项目或业务路径，不得使用 `setwd()`。

R 脚本必须把 `--r-lib-file` 作为必需参数，以 UTF-8 按顺序读取多行 `R.txt` 中的非空、非注释候选，跳过本机不存在的目录，优先选择与当前 R 主次版本一致的第一个包库；只有路径未编码版本号时才可作为备用。选中后将其置于 `.libPaths()` 首位并保留当前 `.libPaths()`，随后检查本脚本所需包。禁止写死个人包库、扫描常见包库或自动安装；没有兼容包库或缺包时安全停并报告配置文件、当前 R 版本、候选判断、缺失包和当前 `.libPaths()`。

R 脚本必须显式处理 UTF-8 和中文路径。PDF 主文件可先写入英文临时路径，再复制到正式中文路径。输出必须检查存在且非空。

图输出固定为 PDF 主文件和 TIF 300 dpi 备用图，不再默认 PNG。必须完整读取并执行 `references/planning/规划规则/输出目录与图形拆分规则.md`：一个 PDF 只能有一页和一个独立主数据图形面板，对应 TIF 也只能包含同一个单图；严禁分面、拼接、嵌套、边际图、多页 PDF、同一设备多次打印、多 grob 或多 viewport。若任务包含多个图，必须拆成多个独立 R 输出和多对 PDF/TIF 文件。候选模板或 R 源码在语义上可能生成上述组合结构时，运行前即判定不合格，不得靠运行后裁切补救。

画布必须偏大，宁可留白也不要截断标题、图例、坐标轴文字、热图行列名。字体必须显式设置且清楚可读，配色默认 Nature 风格、低饱和度。正式运行后还必须核对 PDF 页数为 1，并依据文件、脚本和输出语义确认每个 PDF/TIF 只承载一个主图；任一检查不通过即复现前安全停。

## run_pipeline.ps1
生成 PS1 前，必须完整读取：

- `references/execution/ps1/run_pipeline.template.ps1`
- `references/execution/ps1/reproduce_pipeline.ps1`
- 若任务包含 R：`references/execution/ps1/r_runtime_selection.template.ps1`

先写完自动规划表要求的 Python/R 业务脚本，再把两个 reference 复制到分钟时间戳工作记录叶目录。第一个复制并命名为 `run_pipeline.ps1`；第二个逐字复制并命名为 `reproduce_pipeline.ps1`。两个 reference 固定为 UTF-8 with BOM；复制和填写命令区后必须保留 BOM，以便 Windows PowerShell 5.1 正确读取中文路径和中文字符串。

`run_pipeline.ps1` 是正式运行事实脚本。只允许替换模板中的 `BEGIN PLANNED COMMANDS` 与 `END PLANNED COMMANDS` 区块；模板固定头、`-TestMode`、`$ResearchProjectsRoot`、`$DailyRoot` 和 `$OutputBranch` 不得重写。`NEW_TASK` 和非纯样式微调生成正式结果时必须实际运行：

```powershell
.\run_pipeline.ps1
```

规划命令区必须是自动规划表的机械展开：有 3 个正式脚本就只按规划顺序调用这 3 个脚本。脚本数量、顺序、依赖、输入、输出和参数全部由规划阶段确定；执行阶段不得重新推断或改变。

- 业务脚本位于同一叶目录时，用 `$PSScriptRoot` 定位。
- 历史输入使用自动规划表记录的、`$ResearchProjectsRoot` 之后以项目名开头的项目相对路径，并与 `$ResearchProjectsRoot` 拼接。
- 本次上游输出和本次输出使用 `$DailyRoot`、`$OutputBranch` 与规划表中的相对子路径拼接。
- 正式模式固定写入每日 `结果/单元库`；测试模式固定写入每日 `test/单元库`，目录结构和文件名不变。

传给 Python/R 的可以是运行时绝对路径，但该绝对路径必须由 PS1 每次运行时解析；不得把盘符、用户名或 `$ResearchProjectsRoot` 之前的同步根写入规划表、解释文件或业务脚本。

含 R 任务时，必须把 `r_runtime_selection.template.ps1` 逐字放在规划命令区最前面，准备一次 `$RscriptExe`、可选 `$PlotLibraryRoot`、可选 `$RLibFile` 和 `$RLibraryArgs`，同一 pipeline 的所有 R 命令复用。该固定块是运行环境准备，不是规划表业务步骤：

1. 如果设置了 `RESEARCH_PLOT_LIBRARY_ROOT`，只使用它指向的现有目录；否则仅在 `$ResearchProjectsRoot/绘图模式脚本库` 确实存在时把它作为兼容候选。没有共享绘图库不是阻塞条件。
2. 按顺序尝试 `RESEARCH_RSCRIPT`、共享绘图库中的 `Rscript_exe.txt` 候选和当前 `PATH` 中的 `Rscript`。不得扫描整台电脑或猜测安装位置。
3. 每个候选必须解析为实际文件并运行 `--version`；选择第一个退出码为 `0` 的候选。全部失败时安全停并逐项报告。
4. 共享绘图库中存在 `R.txt` 时设置 `$RLibFile` 并生成 `--r-lib-file` 参数；否则 `$RLibraryArgs` 为空，R 使用自身标准包库配置。
5. 有兼容模板库时可以选用并复制模板；没有时在当前分钟任务内生成参数化、单图、可复现的 R 业务脚本，不得因此引用开发者私有目录。
6. 规划表、解释文件、任务脚本和生成的 PS1 不得固定保存配置中的某一候选行或 `$ResearchProjectsRoot` 之前的路径；实际选择只进入本次运行日志。

`run_pipeline.ps1` 不接收 `-OutputRoot`，不读取 `工作流日志.txt`，不写解释文件，不更新解释汇总表，也不调用 `reproduce_pipeline.ps1`。

纯 R 表现层微调是唯一不先运行正式 `run_pipeline.ps1` 的例外。此时复用原第一个 PS1 中的绘图业务输入、PDF/TIF 输出和其它业务参数，但必须重新执行固定 R 运行时选择 reference，从当前配置重新解析 `$RscriptExe` 与可选 `$RLibraryArgs`；不得复用旧机器绝对路径或电脑专用 TXT。随后直接调用原 R 脚本；不得改变参数名称、输入、变量映射、统计、正式输出路径或图形科研含义。该次修改成功后立即运行原 `reproduce_pipeline.ps1`，由它在 test 分支完整重跑当前第一个 PS1，不再请求第二次确认。

`run_pipeline.ps1` 禁止调用规划表生成、规划表检查、日志生成、解释同步、缓存整理或临时辅助脚本。除固定模板和规划命令所需的路径变量外，禁止堆放与分析无关的通用框架。输出父目录默认由对应 Python/R 脚本内部创建。

## reproduce_pipeline.ps1
`reproduce_pipeline.ps1` 必须从固定 reference 逐字复制，不得按任务重写、插入输出清单、比较策略或 Python/R 命令。它只依赖自身位置和同目录的 `run_pipeline.ps1`：以 `$PSScriptRoot` 确定分钟时间戳叶目录，以上一级确定每日目录，再定位每日 `结果` 与 `test`。

`NEW_TASK` 和非纯样式微调在正式 `run_pipeline.ps1` 成功后，本 skill 必须立即运行；纯 R 表现层微调在该次直接 R 运行成功后立即运行：

```powershell
.\reproduce_pipeline.ps1
```

若直接调用两个 PS1 被 Windows PowerShell 执行策略阻止，可对两个脚本统一使用一次性子进程调用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File <PS1路径>`。不得修改用户级或系统级执行策略；必须在工作流日志记录实际调用方式。

固定脚本先删除上次异常遗留的每日 `test`，再调用同目录的 `run_pipeline.ps1 -TestMode`。运行结束后，它递归遍历 `test` 中实际生成的全部文件，用相同相对路径定位 `结果` 中的正式文件，记录双方存在性、文件大小和 SHA256 到叶目录的 `复现哈希记录.txt`。记录写入成功且非空后删除整个 `test`。

第二个 PS1 只负责客观取证，不读取规划表、不判断复现是否通过。`run_pipeline.ps1 -TestMode` 失败、没有生成 `test`、哈希记录写入失败或固定目录关系不成立时必须安全停。

## 复现比较规则
本 skill 必须读取 `复现哈希记录.txt`，结合自动规划表中的 `复现比较策略` 判断；结论不能写进第二个 PS1。

- `strict_hash`：正式输出和复现输出必须存在，文件大小和 SHA256 必须一致。用于 `.tsv`、`.csv`、`.txt`、`.md`、`.json`、`.xlsx`、`.xls`、`.xml`、`.yaml`、`.yml`、`.html` 等非图形结果。
- `loose_visual`：正式输出和复现输出必须存在、扩展名一致且非空，允许 SHA256 不一致。用于 `.pdf`、`.tif`、`.tiff`、`.svg`、`.png`、`.jpg`、`.jpeg` 等图形输出。
- `auto_by_extension`：用于目录输出。必须递归比较相对文件路径集合；目录内每个文件按扩展名使用 strict 或 loose 规则。

测试文件数量为 0、正式对应文件为 `MISSING`、规划输出没有出现在记录中，或目录的相对文件集合不完整时，均视为复现失败。只有复现判断通过后，才进入 explanation。

## 工作记录目录洁净规则
本 skill 默认不生成临时过程文件。中间数据应在脚本内存中用变量、DataFrame、list、dict 等对象传递。

工作记录叶目录固定保留：

```text
任务说明.md
规划表.xlsx
分析脚本
run_pipeline.ps1
reproduce_pipeline.ps1
复现哈希记录.txt
工作流日志.txt
```

禁止保留临时表、缓存表、中间图、中间 JSON、pickle、rds、调试抽样文件或解释同步脚本。只有工具或数据量确实需要磁盘临时文件时，才允许使用 `temp/` 或 `cache/`，运行结束后清理，并在日志说明原因。

不得在时间戳叶目录保留用于创建、修改、导出或检查规划表的辅助脚本；规划表生成后保留唯一 `任务说明.md` 和 `规划表.xlsx` 本体。普通流程执行阶段对 `任务说明.md` 只读，不作为脚本或 PS1 输入；确认后的历史微调按下述例外处理。不得留下 `write_plan.py`、`build_plan.py`、`export_plan.py`、`inspect_plan.py`、`plan.json`、`plan.csv`、`plan.tsv` 等产物。写日志前必须检查叶目录并清理未规划的辅助脚本、缓存、中间表、`__pycache__`、调试输出、规划表导出副本和复现检查中间目录；不能清理时安全停并在日志说明。

确认后的微调允许按上述影响范围原地更新唯一 `规划表.xlsx` 和 `任务说明.md`，但仍不得创建副本或辅助产物。微调完成后只向原 `工作流日志.txt` 追加一次变更汇总，记录路由确认、受影响文件、正式运行方式、复现结果和 explanation 同步范围。
